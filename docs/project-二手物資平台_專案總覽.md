# 二手物資平台｜專案總覽

> 版本：v1.1（2026-11-08）
> 主辦與受款單位：社團法人好事公益協會｜平台：好事道 GDDAO｜第一個執行夥伴：桃園市荃安長照關懷協會
> 這份文件說明專案的整體架構、使用者、流程與後台。另外兩份文件分工如下：
> - 《skill-二手物資平台助理》：數位員工「二手物資平台助理」在聊天中怎麼問、怎麼處理
> - 《website-二手物資平台官網規格》：官網的頁面、即時資料與按鈕規則

---

## 1. 專案是什麼

一邊是想捐物資的個人與企業，一邊是偏鄉教會、NGO、村長辦公室與需要的家庭。二手物資平台把兩邊接起來，處理即期品、二手傢俱、二手家電、衣物鞋飾，以及活動用的全新禮物。

**一句話**：在好事道聊天 `@二手物資平台助理`，不論是捐物資、需要物資、負責運送，都能把事情辦完；每一件物資送到哪裡、幫了誰，都看得到。

**專案目標**
1. 讓可用的物資不被丟掉，送到真正需要的地方
2. 降低協會的溝通成本：用好事道聊天取代電話和 LINE，進度自動通知
3. 全程透明：送達照片、發放回報、受益戶數都公開（不含個資）
4. 累積影響力資料：好事履歷、滿意度問卷、SROI

**過去的基礎**
- 2021 年起：食物銀行即期品送宜花東部落，17–20 多位牧師協助，每月約 300 戶
- 2025–2026 年：「傢俱接力送光復」馬太鞍災後重建，募款 458 萬元，完成 656 戶傢俱配送，獲第十屆資誠永續影響力獎銀獎
- 2025 年：聖誕禮物送偏鄉，約 44 個教會與單位登記
- 既有網站：guppycubed.com 的二手傢俱捐贈媒合中心（只有捐贈端，需求端過去用 Excel 管理）

## 2. 系統架構

```
                       ┌─────────────── 好事道 GDDAO ────────────────┐
  捐贈者／需求單位 ───▶ │ 聊天：@二手物資平台助理（對外唯一入口）       │
  （手機、電腦）        │ 會員帳號、好事履歷                           │
                       │ 官網（好事道 AI 產生）：需求牆、物資牆、成果 │
                       │ 問卷：滿意度三份                             │
                       │ 待辦、通知：通知執行夥伴窗口                 │
                       └───────────────┬──────────────────────────────┘
                                       │ 工具 API／即時資料 API
                       ┌───────────────▼──────────────────────────────┐
                       │ 物資平台後台（獨立系統，所有資料都存在這裡）  │
                       │ 捐贈單、需求單、媒合、庫存 QR、配送、責信紀錄 │
                       │ 狀態機、品類規則、執行夥伴分派                │
  執行夥伴員工 ──────▶ │ 夥伴後台網頁（荃安主要工作平台）              │
  協會管理員 ────────▶ │ 平台管理網頁                                  │
                       └───────────────────────────────────────────────┘
```

**分工原則**
- **好事道負責「人」**：會員、聊天、通知、問卷、官網、好事履歷
- **物資平台後台負責「物資」**：所有捐贈、需求、庫存、配送的資料與狀態，都以物資平台的資料為準
- **聊天和後台共用同一份資料**：在聊天按「通過」，後台同步更新；在後台審核，聊天也會通知捐贈者
- **捐款**：助理只提供捐款網頁連結，捐款網頁由協會另外製作，不在平台內處理金流
- 物資平台程式：GitHub `supermanbill/good-deeds-resources-donation`（第一期已完成）

## 3. 使用者與權限

| 角色 | 是誰 | 主要入口 | 可以做什麼 |
|---|---|---|---|
| **訪客** | 任何人 | 官網 | 看需求牆、物資牆、活動、成果；點按鈕開始聊天 |
| **捐贈者** | 個人、企業（好事道會員） | 聊天 | 登記捐物資、認領需求、參加活動、查進度、看好事履歷 |
| **需求單位** | 教會、NGO、村長辦公室，以及經轉介的個人家庭（好事道會員，首次需驗證） | 聊天 | 參加活動申請、許願、確認收貨、回報發放、填問卷 |
| **執行夥伴員工** | 荃安等（負責人、審核員、司機） | 夥伴後台網頁＋聊天 | 審核、婉拒、補件、入倉 QR、分配、出貨、聯繫捐贈者 |
| **平台管理員** | 好事公益協會 | 平台管理網頁＋聊天 | 開活動、驗證需求單位、審核許願、管理執行夥伴、改派案件 |

> 「需求單位」包含四種類型：教會、NGO、村長辦公室、個人家庭。個人家庭必須由社工、村長、教會或合作單位轉介，姓名和地址不公開；官網只顯示「〇〇鄉的一戶家庭（由〇〇轉介）」。

**執行夥伴不寫死**：荃安是第一個，之後可以加入第二、第三個。每個夥伴各自設定集貨點、到府收貨的縣市、接收品類、收費規則。到府收貨的案件依地址與品類自動分派，管理員可以改派。

## 4. 品類與收件規則（三份文件以本節為準）

| 品類 | 收件條件 | 照片、影片 | 不收 |
|---|---|---|---|
| 二手家電 | 必須能正常運作；問品牌型號、購買年份 | 外觀、銘牌各 1 張＋運轉短片 10–30 秒 | 無法運作、缺零件、漏水漏電 |
| 二手傢俱 | 結構完整、無蟲蛀；問尺寸、材質、使用年限 | 正面、細節各 1 張 | 蟲蛀、發霉、嚴重破損、有污漬的床墊 |
| 即期品（食品、生活用品） | 常溫保存，有效期限 3 個月以上 | 外包裝、效期標示各 1 張 | 冷藏冷凍品、效期不足 3 個月、已拆封 |
| 衣物、鞋、飾品 | 乾淨、無破損 | 攤開拍 1 張 | 髒污、破損、內衣褲與襪子（全新除外） |
| 活動用全新禮物 | 全新未拆封 | 裝箱內容 1 張 | 食品、月曆、桌曆、筆記本、使用過的物品 |

- 使用年限較久的大型家電、傢俱，由執行夥伴依照片與影片判斷，沒有固定年限

**運送方式**
- **自己送到集貨點**：例如桃園八德倉庫（桃園市八德區和強路 135 之 7 號；收貨時段【待確認】）。審核通過前不要直接送
- **請夥伴到府收**：運費由捐贈者負擔，夥伴審核後在好事道確認時間與費用。服務範圍、收費方式與執行單位見第 12 節【待確認】
- 從集貨點送往偏鄉的運費和人力由協會負責（靠捐款支持）

## 5. 主要流程

### 流程一：捐物資

| 步驟 | 誰 | 在哪裡 | 做什麼 |
|---|---|---|---|
| 1 | 捐贈者 | 聊天 | `@二手物資平台助理` 說要捐，助理依品類逐項問、收照片影片、問運送方式 |
| 2 | 助理 | 聊天 → 後台 | 確認摘要後建立捐贈單（單號 D-yyyymmdd-xxxx），通知負責的執行夥伴 |
| 3 | 執行夥伴 | 夥伴後台 | 審核：通過／婉拒（選原因）／要求補件；通知自動送給捐贈者 |
| 4 | 捐贈者或夥伴 | — | 自己送到集貨點，或夥伴到府收 |
| 5 | 執行夥伴 | 夥伴後台 | 入倉：每箱或每件產生一個 QR 碼，列印標籤 |
| 6 | 執行夥伴 | 夥伴後台 | 分配給需求單位（可以手動，或依截止日自動拆單） |
| 7 | 執行夥伴 | 夥伴後台 | 出貨，通知需求單位準備收貨 |

### 流程二：許願 → 認領

| 步驟 | 誰 | 在哪裡 | 做什麼 |
|---|---|---|---|
| 1 | 需求單位 | 聊天 | 提出需求：品項、數量、頻率（一次、每月、每季）、用途、收貨資訊 |
| 2 | 平台管理員 | 平台管理 | 驗證單位、審核；通過後公開到官網需求牆 |
| 3 | 捐贈者 | 官網 → 聊天 | 在需求牆按「我來捐」，助理帶入該需求，接著走流程一 |
| 4 | 系統 | — | 依數量更新進度（部分媒合、已媒合），通知需求單位 |

- 定期需求每 3 個月請需求單位重新確認，沒有回覆就暫停公開；結案後自動開下一期

### 流程三：活動（例如聖誕禮物送偏鄉）

1. 平台管理員開活動：期間、收件規則、捐款金額表（例如依箱數分級）
2. 企業和個人透過聊天登記捐贈；教會與單位透過聊天申請
3. 執行夥伴集中收貨、入倉、依各單位人數分配、配送
4. 單位收到後拍照，活動當天回報發放成果

### 流程四：收貨與發放回報

1. 物資出發 → 通知需求單位
2. 到貨 → 掃箱上的 QR 碼，或在聊天回覆「收到了」並拍照
3. 全部到齊 → 請需求單位回報：送給幾戶家庭、用在哪個活動、現場照片（不拍可辨識的兒童正臉、不寫家庭姓名）
4. 回報完成 → 結案 → 通知捐贈者成果 → 記入雙方好事履歷 → 發送滿意度問卷
5. 需求單位不方便操作時，執行夥伴可以代傳

### 流程五：電話備援

- 好事道訊息超過 24 小時沒讀，夥伴後台列出需要打電話的名單
- 電話只給被指派的夥伴員工、司機、協會管理員看
- 在聊天中，助理只對「被指派該案件的夥伴員工」與協會管理員顯示電話，而且只顯示他負責的案件；其他人問，一律請他到夥伴後台查看

## 6. 狀態定義

**捐贈單**
已送出 → 審核中 →（已婉拒｜待補件 → 審核中）→ 已通過 → 待送達／待取件 → 已入倉 → 已媒合 → 配送中 → 已送達 → 已結案

**需求單**
已送出 → 審核中 →（已婉拒｜公開募集中（許願）｜已核准（活動））→ 部分媒合 → 已媒合 → 配送中 → 已收貨 → 待回報發放 → 已結案

（「已收貨」之後系統會立刻轉為「待回報發放」，所以通知時合併為一則：「已確認收貨，請回報發放情形」）
（定期需求逾期未確認 → 暫停公開 → 確認後恢復）

每次狀態改變，都在同一個聊天對話串通知相關的人。

## 7. 後台

### 7.1 夥伴後台（執行夥伴員工的主要工作平台）

**第一期已完成**
- 案件清單：待審核、待送達／待取件、在倉庫待分配、已分配／配送中
- 捐贈單詳情：捐贈者資料、物資明細、照片影片、品類確認事項、處理紀錄
- 審核：通過（附送貨安排）、婉拒（標準原因＋說明）、要求補件
- 入倉：選集貨點、填箱數，產生 QR 碼並列印標籤
- 分配：手動選需求，或自動依截止日分配；數量不足時部分媒合
- 出貨、收貨資訊（電話只給被指派的夥伴）、代傳發放回報
- 電話備援名單、傳訊息給捐贈者

**下一期規劃**
- 搜尋與篩選（單號、品類、縣市、日期）
- 案件指派給員工
- 到府收貨排程（約定時間、報價、每日收件清單）
- 批次操作（多筆通過、多筆列印 QR）
- 內部備註（只給員工看）

### 7.2 平台管理（好事公益協會）

- 審核需求與驗證需求單位
- 管理執行夥伴：新增、停用、集貨點、到府範圍、收件品類、人員
- 改派未分派或分派錯誤的案件
- 開活動、設定捐款金額表
- 定期需求檢查（暫停逾期未確認的需求）

## 9. 隱私與營運規則

- 電話、詳細地址只給被指派的夥伴員工、司機、協會管理員；公開頁只顯示到縣市＋鄉鎮
- 受益家庭不記姓名；公開照片避免可辨識的兒童正臉
- 收不收件由執行夥伴人工審核，助理只做資料收集和初步檢查
- 不承諾運費金額、到府時間、一定媒合成功
- 一般捐贈和需求不要求先捐款才受理（活動另有規定除外）
- 用「聖誕節」，不用「耶誕節」
- 品牌用語：好事公益協會（主辦、受款）、好事道 GDDAO（平台）、執行夥伴（荃安等）
