# 二手物資平台官網｜網站規格（給好事道 AI 網站產生器）

> 版本：v1.1（2026-11-08）｜主辦與受款單位：社團法人好事公益協會｜平台：好事道 GDDAO
> 用途：交給好事道 AI 產生官網。網站本身**不收表單**，所有「我要捐」「我需要」「查進度」按鈕都打開好事道聊天的 `@二手物資平台助理`。網站負責「讓人看見現況、按下行動」，聊天負責「把事情辦完」。

---

## 1. 網站目標

1. **即時呈現兩邊的現況**：偏鄉單位需要什麼（需求牆）、捐贈者願意提供什麼（物資牆）、正在進行的活動、已經完成的成果
2. **一鍵開始行動**：看到需求就能點「我來捐」，直接進入助理對話，帶著該需求的資料
3. **建立信任**：每一筆物資送到哪裡、照片、受益戶數都公開（不含個資），讓捐贈者放心
4. **支持運費**：讓人知道物流和人事要花錢，並提供捐款入口

**主要對象**：
- 捐贈者：個人、企業 ESG 窗口
- 需求方：偏鄉教會、NGO、村長辦公室
- 執行夥伴：荃安等，可以從網站進入後台

---

## 2. 網站架構

```
首頁
├─ 需求牆（許願池）      /needs
│   └─ 需求詳情          /needs/{code}
├─ 物資牆（可申請的物資） /offers
├─ 專案活動              /campaigns
│   └─ 活動詳情          /campaigns/{slug}
├─ 成果與責信            /impact
├─ 怎麼運作              /how-it-works
├─ 捐款支持運費          /give
└─ 常見問題              /faq
```

## 3. 頁面內容

### 3.1 首頁

**① 主視覺**
- 主標：**一邊有物資想捐，一邊有需要。好事道幫你們接起來。**
- 副標：即期品、二手傢俱、家電、衣物，經過執行夥伴審核，送到偏鄉教會、NGO、村辦與需要的家庭。每一件送到哪裡、幫了誰，都看得到。
- 三個主要按鈕（都開啟聊天）：
  - 〔我要捐物資〕→ `intent=donate`
  - 〔我們需要物資〕→ `intent=need`
  - 〔捐款支持運費〕→ `/give`

**② 即時數字列**（資料來源：`stats`，每 5 分鐘更新）
- 已送達物資件數｜受益家庭戶數｜服務單位數｜執行夥伴數｜本月新增需求

**③ 進行中的活動**（最多 3 個卡片）
- 卡片：活動名稱、截止日、進度條（已募／目標）、〔我要參加〕

**④ 最新需求**（6 筆，連到需求牆）
- 卡片：單位名稱、地區（縣市＋鄉鎮）、需要的品項、還缺多少（進度條）、頻率標籤（每月、每季）、截止日、〔我來捐〕

**⑤ 物資牆精選**（6 筆，連到物資牆）
- 卡片：物資照片、品項、數量、所在縣市、〔我們需要〕

**⑥ 最新送達故事**（3 筆，連到成果頁）
- 發放現場照片、一句收受單位的話、「〇〇部落・12 戶家庭」

**⑦ 怎麼運作**（四步驟圖示）
1. 在好事道聊天告訴助理 → 2. 執行夥伴審核 → 3. 入倉、配送 → 4. 拍照回報、結案

**⑧ 加入好事道的好處**（沿用「為什麼要加入好事道」文案）
- 即時進度、一個對話聯絡所有人、好事履歷、看得見的影響力
- 說明：協會省下的電話和人事費，可以多付一趟偏鄉運費

**⑨ 合作夥伴 Logo 列**：社團法人好事公益協會、桃園市荃安長照關懷協會、航通興業有限公司（Logo 檔由協會提供）

### 3.2 需求牆 `/needs`

- **篩選**：品類（家電、傢俱、即期品、衣物、禮物）、地區（縣市）、頻率（一次性、定期）、急迫度（14 天內截止）
- **排序**：截止日近的在前（預設）、最新、還缺最多
- **卡片欄位**：
  - 單位類型標籤（教會、NGO、村辦、家庭）＋單位名稱；個人家庭只顯示「〇〇鄉的一戶家庭（由〇〇轉介）」
  - 地區：縣市＋鄉鎮
  - 標題、品項與數量、進度條（已到位／需要）
  - 頻率與截止日標籤
  - 〔我來捐〕→ 開啟聊天 `intent=claim&needItem={id}`
- **空狀態**：「目前沒有符合的需求，您可以直接把想捐的物資告訴助理，我們幫您找需要的地方。」〔告訴助理〕

### 3.3 需求詳情 `/needs/{code}`

- 標題、單位、地區、受益人數、用途說明
- 需要的物資清單：每一項都有進度條和〔我來捐〕
- 定期需求：「每月需要，目前是第 3 期」
- 已認領紀錄：「王〇明 認領 10 包・11/8」（捐贈者名稱可以匿名）
- 送達與發放紀錄：照片、日期、受益戶數
- **不顯示**：電話、詳細地址、受益家庭姓名

### 3.4 物資牆 `/offers`

- 捐贈者勾選「公開到物資展示牆」、而且已經審核通過的物資
- 卡片：照片、品項、數量、狀況簡述、所在縣市、在哪個集貨點
- 〔我們需要〕→ 開啟聊天 `intent=request_offer&offer={id}`（只有已驗證的需求單位可以申請；未驗證的由助理引導先完成驗證）

### 3.5 專案活動 `/campaigns`、`/campaigns/{slug}`

- 活動說明、期間、收件規則（例如聖誕禮物只收全新未拆封，不收食品、月曆、桌曆、筆記本）
- 兩個行動按鈕：
  - 〔我要捐贈〕→ `intent=donate&campaign={slug}`
  - 〔我們的單位想申請〕→ `intent=need&campaign={slug}`
- 捐款金額表（如果有）：例如 6,000 元／15 箱以內 … 30,000 元／86–100 箱
- 參加單位地圖：參加活動的教會分布（只到鄉鎮）
- 即時進度：已募箱數、已登記單位數、已送達單位數

### 3.6 成果與責信 `/impact`

- 總數字：送達件數、受益戶數、服務單位數
- 縣市分布：依 feed 的 `areas` 顯示各縣市送達件數（列表或簡易地圖）
- 依活動、品類篩選
- 故事牆：發放現場照片＋收受單位的回饋（取自 feed 的 `stories`）
- 滿意度摘要：**等三份問卷建立並有回覆後才顯示**；在那之前不放這個區塊
- 企業專區、重量統計：第二期再做，第一版不放

### 3.7 怎麼運作 `/how-it-works`

用三條路線說明，每條都有〔開始〕按鈕：
- **我要捐物資**：可以捐什麼、不收什麼、運送方式（自己送到集貨點，或請夥伴到府收、運費自付）、捐物收據說明
- **我們需要物資**：誰可以申請、要準備什麼證明、審核要多久、收到後要回報
- **執行夥伴**：如何加入成為執行夥伴

品類收件規則表（**照抄《專案總覽》第 4 節，不另外增減**）：

| 品類 | 收件條件 | 不收 |
|---|---|---|
| 二手家電 | 能正常運作；需要型號、購買年份、照片 2 張、運轉影片 | 無法運作、缺零件、漏水漏電 |
| 二手傢俱 | 結構完整、無蟲蛀；照片 2 張、使用年限 | 蟲蛀、發霉、嚴重破損、有污漬的床墊 |
| 即期品 | 常溫保存、有效期限 3 個月以上 | 冷藏冷凍品、效期不足 3 個月、已拆封 |
| 衣物、鞋、飾品 | 乾淨、無破損 | 髒污、破損、內衣褲與襪子（全新除外） |
| 活動用全新禮物 | 全新未拆封 | 食品、月曆、桌曆、筆記本、使用過的物品 |

到府收貨的範圍、運費、捐物收據開立單位：見《專案總覽》第 12 節，**確認前頁面寫「詳情請洽助理」，不要自行填入**。

### 3.8 捐款 `/give`

- 用途卡片：物流費（17 噸貨車北部到花蓮一趟約 2.5 萬元）、人事費、倉儲費、活動費用、一般捐款
- 捐款按鈕帶用途參數，連到**協會另外製作的捐款網頁**（網址待協會提供，確認前按鈕顯示「即將開放」）。平台內不處理金流
- 透明說明：受款單位是社團法人好事公益協會，每筆支出公開在成果頁
- 範例支出結構圖（參考光復專案：人力 34%、物流 29%、物資 22%、倉儲 9.5%）

### 3.9 常見問題 `/faq`

- 一定要加入好事道嗎？為什麼？
- 長輩不會用怎麼辦？（可以由家人代辦，或請轉介的教會、村辦協助；協會服務電話待確認，確認前不寫電話）
- 到府收貨要多少錢？
- 東西被婉拒的話怎麼辦？
- 捐物收據怎麼開？
- 我的電話和地址會被公開嗎？
- 個人家庭可以申請嗎？（需要社工、村長或教會轉介）

## 4. 開啟聊天的連結規則

所有行動按鈕都開啟好事道聊天，並帶入參數，讓助理不必再問一次：

```
{好事道聊天網址}?agent=二手物資平台助理&intent={intent}&{參數}
```
（`{好事道聊天網址}` 由 Mason 依好事道 deep link 規則提供，確認前先用 `#` 佔位）

| 按鈕 | intent | 參數 |
|---|---|---|
| 我要捐物資 | `donate` | `campaign`（選填）、`category`（選填） |
| 我來捐（認領需求） | `claim` | `needItem` |
| 我們需要物資 | `need` | `campaign`（選填） |
| 我們需要（申請展示物資） | `request_offer` | `offer` |
| 查詢進度 | `status` | `code`（選填） |
| 我是執行夥伴 | `partner` | — |

每個 intent 對應助理的流程：`donate` → 流程 A、`need` → 流程 B、`claim` → 流程 C、`partner` → 流程 D、`status` → 流程 F、`request_offer` → 流程 H。

> 實際網址格式依好事道聊天的 deep link 規則調整。未登入的人點了，要先登入或註冊，完成後**自動回到對話並保留參數**。

## 6. 設計規範

- **品牌**：使用好事道 GDDAO 的 Logo 與配色；頁尾寫「主辦與受款單位：社團法人好事公益協會｜技術平台：好事道 GDDAO」
- **手機優先**：大部分使用者用手機；卡片單欄排列，按鈕要大，方便點按
- **長輩友善**：內文字級 17px 以上、行高 1.7、高對比；不只用顏色表達狀態（另外加文字標籤）
- **照片**：用真實的送達與發放照片；不用素材庫的假照片
- **用語**：台灣繁體中文；用「聖誕節」；「執行夥伴」「需求單位」「捐贈者」用詞統一
- **語氣**：溫暖、具體、用數字說話，避免煽情或悲情化偏鄉

## 7. 隱私規則（必須遵守）

- 地址只顯示到縣市＋鄉鎮；不顯示電話、Email
- 個人家庭不顯示姓名，只寫「〇〇鄉的一戶家庭（由〇〇轉介）」
- 捐贈者預設匿名（例如「王〇明」或「一位熱心捐贈者」），企業可以選擇具名
- 照片避免可辨識的兒童正臉；上傳前由收受單位確認同意

## 8. 驗收清單

- [ ] 首頁三個主要按鈕都能開啟聊天並帶入 intent
- [ ] 需求牆的〔我來捐〕會帶入正確的 `needItem`
- [ ] 即時數字與需求清單跟後台一致（誤差 5 分鐘以內）
- [ ] 公開頁面原始碼中找不到任何電話號碼或詳細地址
- [ ] 手機（375px 寬）瀏覽，所有按鈕都點得到、文字不會被切掉
- [ ] 資料讀不到時，頁面不會空白
